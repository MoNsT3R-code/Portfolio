Who owns the interface? Agentic UI in one page

A synthesis of five sources on A2UI, AG-UI, MCP Apps and small-model UI generation.

Chat is a poor fit for picking dates, approving requests or comparing options. The industry response is to let agents produce interactions, and the real design question is who owns the UI: the application, the model, or the tool.

A separate layer, AG-UI, is not a UI format at all. It keeps the frontend and a running agent in sync (streaming, tool calls, state, user events) and can carry A2UI or MCP payloads.

What the research shows

  • Frontier models need the schema in the prompt. On A2UI-Bench, GPT-5.4 scored 23.9 overall with only light instructions and 74.1 with the full schema (Macaron-A2UI, Mind Lab).
  • Training can replace long prompts. A Qwen3-235B model went from 21.6 to 63.6 with supervised fine-tuning and 74.2 after reinforcement learning, matching the prompted frontier baseline.
  • Small models can be enough. An Amazon study found a fine-tuned 4B model recovered about 98% of teacher semantic quality and 97% of visual quality at over 10x lower cost than frontier APIs, and ran in roughly 8 seconds versus 19 to 23 for Sonnet or Opus.
  • Train the model to read the catalog. Shuffling and renaming components during training beat the plain baseline; a richer catalog (up to about 100 components) helped even 0.8B models.

What to weigh

  • Governed workflows (approvals, KYC, infrastructure changes) favor A2UI: consistent native UX, strong control over rendering.
  • Specialist experiences (seat maps, product configurators, analytics dashboards) favor MCP Apps: teams ship independently, at the price of consistency.
  • Failure modes differ. A2UI fails through malformed or unsupported schemas and lost state. MCP Apps fail through dropped messages and sandbox misconfiguration.
  • Memory and payload: iframes add a runtime per embedded app, while A2UI payloads are small JSON, though web assets cache well.

Recommendation

Treat these as layers, not rivals. Use MCP for tool access, the application or A2UI for core governed workflows, MCP Apps for specialist third-party surfaces, and AG-UI where the frontend must stay live with the agent. Introduce structured UI incrementally, starting with high-friction steps such as approvals, rather than replacing chat at once.

Caveats: the protocols are still evolving (A2UI v0.8 stable, v0.9 draft). Both studies use single-turn tests and LLM judges; the Amazon study did no user testing. The Happiest Minds ratings are qualitative vendor analysis, and the CopilotKit document is written from the AG-UI maintainers' perspective. The ASD legacy-technology kit was left out because it is unrelated.
