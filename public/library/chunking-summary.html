RESEARCH SUMMARY — TEAM AI SYNC

Chunking Strategies Evaluation Framework

Which chunking strategy should we use, for which data, and why — backed by a working test lab and a 29-case evaluation.
Prepared for: Hadia & Musfira  ·  Version 1.0 — September 2026

Chunking shapes everything downstream in a RAG system: retrieval accuracy, context preservation, response quality, latency, and cost. No single strategy wins across every data type, so this project built and ran ten chunking strategies against a shared evaluation set to find out which one to reach for, and when.

Built →A working, interactive lab implementing all 6 core strategies live on real text
Tested →29 test cases across 3 real document types, scored on 5 metrics
Learned →Failures are systematic and traceable to specific chunk-boundary decisions
Recommend →A 3-tier decision framework, not a single "best" strategy
01 — What we researched & built

Ten chunking approaches, one shared test bed

We implemented the six strategies in scope, then went further and evaluated four advanced "upgrade path" techniques for completeness. To make the comparison tangible (not just theoretical), we also built a live playground: paste any text, run it through each strategy, and see the actual chunks, chunk count, size distribution, estimated tokens, and processing time.

Core strategies (in scope) — jump to results:

Fixed-Size Recursive Semantic Sliding Window Structure-Based Hierarchical

Fixed-Size Chunking

Slices text at a constant character count, with optional overlap. Fast, predictable, blind to meaning.

Best for: quick baselines, uniform short-form text, prototyping — see score →

Recursive Chunking

Tries separators in order — paragraph, line, sentence, word — falling back only when a piece still won't fit.

Best for: general-purpose default when structure is mixed or unknown — see score →

Semantic Chunking

Groups sentences by similarity, starting a new chunk when the topic shifts.

Best for (in theory): narrative prose, research papers, topic-shift-heavy content — see score →

Sliding Window Chunking

Windows of N sentences that overlap with the next window, trading duplicated tokens for continuity.

Best for: conversational transcripts, dialogue, streaming logs — see score →

Structure-Based Chunking

Splits directly on headings and paragraph boundaries so each chunk maps to a real section of the source.

Best for: markdown/HTML docs, code, technical documentation — see score →

Hierarchical Chunking

Keeps a parent chunk per section plus smaller child chunks nested inside it for precise retrieval.

Best for: legal contracts, long manuals, multi-level documents — see score →

Advanced techniques (explored beyond scope) — jump to results:

Contextual Retrieval Late Chunking Adaptive Chunking Sentence-Based (baseline for comparison)
Methodology: Three representative documents (Employee Leave Policy, a Technical Manual, and a Legal Contract) were each indexed with all ten strategies, then queried with a shared set of 29 test questions spanning fact retrieval, reasoning, summarization, and context preservation / cross-reference. Every strategy was scored on the same five metrics: retrieval accuracy, context preservation, response quality, latency, and token usage.

Key findings

1

Semantic chunking underperforms consistently. Naive sentence-level splitting scored lowest on all three documents (16/30) — it kept separating headings and labels from the bullet-list content needed to answer questions.

2

Structure-Based is the strongest practical strategy. It matched the top score (30/30) while using the fewest tokens of any high scorer — no overlap or duplication needed.

3

Sliding Window matches top accuracy, but at a cost. Overlapping content adds roughly 1.5–2× the token volume of Structure-Based for the same result.

4

Recursive is the best low-cost default. 27/30 with no special configuration — a safe starting point for general, unstructured content.

5

Hierarchical needs careful tuning. Aggressive child-chunk splitting can reintroduce the same list-from-header fragmentation seen in Semantic Chunking.

6

Contextual Retrieval, Late Chunking, and Adaptive Chunking reach the highest ceiling (30/30 each), especially on cross-referenced content — but they're the most expensive and operationally complex options.

7

Failures were systematic, not random. Every error traced back to a specific chunk-boundary decision — list fragmentation, section separation, or a broken cross-reference — giving a reproducible evidence base for the recommendation.

03 — Trade-offs: quality, speed & cost

No strategy wins on every axis

The strategies that score highest are also the most expensive to run. The decision is rarely "which is best" — it's "which trade-off fits this data and this budget."

04 — Recommendation & decision framework

What we'd recommend, and why

"For this type of data and use case, which chunking strategy should we choose, and what evidence supports that decision?" — this is the question the framework below is built to answer.

DEFAULT — general articles, policies, reports

Start with Recursive Chunking (~512 tokens)

Delivered 27/30 across every document type tested, with no added complexity. It's the safest starting point when a document's structure is mixed or unknown.

STRUCTURED CONTENT — technical manuals, legal contracts, policies with headings/clauses/tables

Switch to Structure-Based Chunking

Tied for the top score (30/30) while using the fewest tokens of any high-scoring strategy. If nesting is deep, upgrade to Hierarchical.

HIGH-VALUE / CROSS-REFERENCE HEAVY — low-volume, high-stakes corpora

Reserve Contextual Retrieval, Late Chunking, or Adaptive Chunking

Justify the added LLM/compute cost with measured accuracy gains — these are for cases like legal cross-references or long, interlinked documents, not general use.
